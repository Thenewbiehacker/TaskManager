NITC HQ TASKS · AGENT GUIDE

Manage tasks on request.

This guide is for a chat agent with folder access that adds tasks on request: for example, when the user says “I have this work today, add it”, use the local REST API or MCP tools below to add, find, update, complete, or reopen tasks in the NITC HQ Tasks store.

Adding a task

Create a task only for concrete work the user has asked to do. Search first (see Finding tasks) so you do not create duplicates.

FieldSemantics
titleShort description of the work. Required; keep the user's wording.
typeCoursework for course work, Miscellaneous for non-course work. Infer from the request.
courseCoursework requires one supported course — pick the best match from: General Physics Lab, Thermodynamics, Engineering Graphics, Mechanics, Mechanical Workshop, Mathematics I, Chemical Structure and Bonding, IIT Madras — Programming with Python, or IIT Madras — English 1. Miscellaneous must have no course (null).
dueDateDate-only YYYY-MM-DD string or null. Interpret “today”, “tomorrow”, and other clear relative dates in the Asia/Kolkata timezone; ask when the intended date is ambiguous. Do not invent a deadline.
notesKeep the user's specifics here. Do not invent a course, requirement, deadline, or result to fill an empty field.
priorityInfer priority from urgency, consequences, and emphasis. Use an integer from 1 (lowest) to 10 (highest); leave it null only when genuinely unknown or preserving an imported blank.
doneNew tasks start not done (false). Change completion only through the complete/reopen actions.

Create with POST /api/tasks:

curl -X POST http://127.0.0.1:4173/api/tasks \
  -H 'content-type: application/json' \
  -d '{"title":"Mechanics problem set 4","type":"Coursework","course":"Mechanics","dueDate":null,"notes":"User said: I have this work today, add it","priority":4}'

Edit fields with PATCH /api/tasks/:id, or with the update_task MCP tool. Use the task's exact ID; search first when the user describes a task by name.

Finding tasks

  • List and search with GET /api/tasks?view=todo&course=...&q=...: view is todo, done, or all; course filters by course name; q matches title and notes.
  • Fetch one task with GET /api/tasks/:id.
  • With MCP, use search_tasks (keyword search) and list_tasks (filtered listing) before creating, and get_task with the exact ID before editing or changing completion.

Completing & reopening

  • Mark complete with POST /api/tasks/:id/complete or the complete_task MCP tool; reopen with POST /api/tasks/:id/reopen or the reopen_task MCP tool.
  • Use the task's exact ID. Search first when the user describes a task by name.
  • If a completion request could refer to more than one task, ask which one before changing anything.
  • Never delete tasks. Completing keeps them in history; reopen them when the user requests it.

MCP tools summary

Available MCP tools: list_tasks, search_tasks, get_task, create_task, update_task, complete_task, reopen_task, and list_courses. The agent interface intentionally has no delete tool. Read each tool description and schema before calling it.

Safety rules

  • Never delete tasks. Complete or reopen them instead.
  • Search before creating; do not create duplicates. Create a task only for concrete work the user has asked to do.
  • Infer Coursework vs Miscellaneous with the exact supported course list above; Miscellaneous must have no course (null).
  • Interpret relative dates in the Asia/Kolkata timezone; store due dates as date-only YYYY-MM-DD values or null.
  • Infer priority as an integer from 1 to 10, or null only when genuinely unknown.
  • If a completion request could refer to more than one task, ask which one before changing anything.
  • Do not invent a deadline, course, requirement, or result. Do not schedule reminders. The app does not create reminders automatically.

Scope note: a design-polish request authorizes presentation changes only, which is outside this task-management workflow — this guide covers tasks only.
