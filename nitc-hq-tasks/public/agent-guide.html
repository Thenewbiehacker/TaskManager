NITC HQ TASKS · AGENT GUIDE

Work with the task desk carefully.

Use these instructions when reading or changing tasks through the website, REST API, or MCP server. The app is a local task tracker seeded from a one-time Notion snapshot; its SQLite database is the current source of truth. It does not sync with Notion.

Before changing tasks

  1. For a new task, search existing tasks or list open tasks first. Do not create duplicates.
  2. Create a task only for concrete work the user has asked to do. Do not turn possibilities, suggestions, or questions into tasks without the user asking.
  3. Use the task's exact ID when editing or changing completion. Search first when the user describes a task by name.
  4. If a completion request could refer to more than one task, ask which one before changing anything.
  5. Never delete tasks. Completing keeps them in history; reopen them when the user requests it.

Classify each task

  • Coursework requires one supported course. Pick the best match from: General Physics Lab, Thermodynamics, Engineering Graphics, Mechanics, Mechanical Workshop, Mathematics I, Chemical Structure and Bonding, IIT Madras — Programming with Python, or IIT Madras — English 1.
  • Miscellaneous is non-course work and must have no course (null).
  • Infer priority from urgency, consequences, and emphasis. Use an integer from 1 (lowest) to 10 (highest); leave it null only when genuinely unknown or preserving an imported blank.
  • Keep the user's specifics in notes. Do not invent a deadline, course, requirement, or result to fill an empty field.

Dates and reminders

  • Store due dates as date-only YYYY-MM-DD values or null.
  • Interpret “today”, “tomorrow”, and other clear relative dates in the Asia/Kolkata timezone. Ask when the intended date is ambiguous.
  • Do not schedule reminders. The app does not create reminders automatically.

Available interfaces

The local web app is served at http://127.0.0.1:4173. Its REST API supports task listing and search, fetching one task, creation, editing, completion, and reopening. MCP clients can use list_tasks, search_tasks, get_task, create_task, update_task, complete_task, reopen_task, and list_courses. Read each tool description and schema before calling it; use search/list before creation and exact IDs for changes.

Task fields are id, title, course, type, dueDate, notes, priority, done, createdAt, and updatedAt. API paths and local MCP setup are documented in the project README.

For agents asked to improve the design

Keep the workflow and records unchanged. A design-polish request authorizes presentation changes only. Preserve task behavior, the database and seed snapshot, REST/MCP contracts, classification rules, priority semantics, and date handling. Do not write to Notion.

In the project source, follow AGENTS.md: design-only work belongs in the stylesheet and presentation-only markup. Preserve existing element IDs, form names, data attributes, labels, and keyboard and mobile access.
